Landing page · element concepts

Twelve new pieces for the landing page

Each one is drawn in the page's current style: same tokens, type, ruled column and canvas cards. Pick the ones you like and they drop into the existing page without touching the rest of the app.

Element 01

Prompt to diagram

A row of things people ask their agent ('Map this repo', 'Add a RAG pipeline', 'Plan a SaaS with Stripe'). Pick one and you see the agent's .arch and the diagram it draws, so the hero shows the agent half of the product, not only the canvas.

Goes in
Hero, under the buttons (in place of, or beside, the typed agent prompt line)
Reuses
AgentPromptLine, the sandbox's SourcePane highlighting, canvas cards
Effort
M

Software architecture for your agents.

Drag and drop your system architecture onto a canvas, or let your agent write Archer code to do it for you.

Element 03

Linked source in the sandbox

Hovering a line of code lights up the component it draws, and hovering a component lights its lines. Changed lines flash the way they do today. It makes 'the canvas is the code' obvious in one gesture.

Reuses

Element 04

  
Agent session replay

  
A short, looping transcript of a coding agent using the MCP tools: it reads the guide, writes a document, gets rejected with E101, fixes it and saves. A small canvas beside it updates on each call.

  
Goes in
New band between the sandbox and Features
Reuses
Canvas cards, Chip, the hero's terminal caret
Effort
M

Element 06

  
Revision scrubber

  
The History tile gets a slider. Drag it through six revisions and the mini canvas changes with it, while the diff list shows what was added, removed or changed and who did it. Box moves are listed as not counting.

  
Goes in
Replaces the visual in the 'History with real diffs' tile
Reuses
History tile's diff rows, canvas cards, Chip
Effort
M

350+ component types

Element 09

  
Try to break it

  
A tiny editor with three classic agent mistakes to try. Each one comes back with the real error code and 'Rejected, not saved', and the canvas beside it stays as it was.

  
Goes in
New tile in Features, or under the FAQ answer about agents getting it wrong
Reuses
@archer/lang validate (real codes E101, E002, E004), CodeMirror styling
Effort
M

Agent writes go through the same validation as the canvas. A broken edit comes back with its error code and line, and the last good revision stays as it was.
