How it reads

      
The model is the diagram. The diagram is the code.

    

    

      
On the canvas drag

      
Pick from 80+ component types, draw connections, gather parts onto planes. Every move writes valid Archer code.

    

    

      
In the file .arch

      
Plain text you can diff, review and keep in your repo. Edit it and the canvas redraws. Positions stay out of the way.

    

    

      
From your agent mcp

      
Any MCP client reads and writes the same document, checked by the same validator the canvas uses.

Notes on the model

        
What sits inside each piece.

        

          
Linked to your repo
Link a GitHub repo and branch. The .arch file on the branch is the truth; src paths open the code, and commits sit next to revisions.

          
Data inside components
Attach a schema, an API contract or notes as JSON, YAML or tables, validated as you type. Your agent reads all of it.

          
Agent safety
Agent writes pass the same validation as the canvas. A broken document is rejected, not saved, and agent edits are badged until you review them.

Questions

        
Before you start.

      

      

        
Do I need an account to try it?
No. Every example opens in a sandbox in your browser. Sign in when you want to keep a model.

        
Which agents work?
Any MCP client: Claude Code, Codex, Cursor, Gemini CLI, VS Code and the rest.

        
Can I start from an existing codebase?
Yes. Copy the agent prompt into your agent and it maps the repo into a model.

        
Can I use my own components?
Yes. Make custom types with their own name, glyph and color, from the canvas or from your agent.
